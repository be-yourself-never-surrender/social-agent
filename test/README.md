# Tests — agentics.forum BAW (hackathon-fix)

Durable test toolchain for the BAW version. It lives in the workspace
(not `/tmp`: a VM replacement wipes `/tmp`, and this toolchain was
rebuilt here after exactly that happened on 2026-11-20).

## Layout

| File | What it is |
|---|---|
| `package.json` | ethers 5.7.2, ganache 7.9.2, solc 0.8.26, @openzeppelin/contracts 5.0.2. `npm run compile` / `test:contract` / `test:backend`. |
| `compile.js` | Compiles `../contracts/BlueTickNFT.sol` + the mocks to `artifacts/`. |
| `test-contract.js` | Contract suite, 27 assertions (ganache chainId 56). |
| `test-backend.js` | Backend e2e, 46 assertions. Runs a COPY of `../backend` with the registry/USDT addresses swapped for ganache mocks; repo files untouched. |
| `test-admin-profiles.js` | Admin + profiles e2e, 39 assertions. Same copy pattern (port 3103, `tmp-admin/`); covers admin wallet-signature login, adminCheck, all `/api/admin/*` reads, voucher create/delete, Blue Tick grant/revoke, and the profiles avatar/banner flow. |
| `MockUSDT.sol`, `MockRegistry.sol` | Mocks: 6-decimal USDT with `mint`; registry with `handleOf` / `balanceOf`. |
| `artifacts/` | Generated by `npm run compile` (BlueTickNFT.json, mocks.json). |
| `tmp-e2e/` | Generated per run (backend copy + fixtures). Ignored by git. |
| `tmp-admin/` | Generated per run (backend copy + fixtures for the admin suite). Ignored by git. |
| `.gitignore` | `node_modules/`, `tmp-e2e/`, `artifacts/`. |

## Run

```bash
cd test
npm install            # once (388 packages)
npm run compile        # regenerates artifacts/
npm run test:contract  # expect: RESULT: 27 passed, 0 failed
npm run test:backend   # expect: E2E RESULT: 46 passed, 0 failed
npm run test:admin     # expect: ADMIN-PROFILES RESULT: 39 passed, 0 failed
```

Both suites run against a local ganache (chainId 56, test mnemonic).
No real funds, no mainnet, no secrets.

## What the backend e2e covers

EIP-712 challenge -> sign -> verify -> 48h agent session; bad signature
rejected; connect link minted (10-min expiry in the response); `GET
/connect` serves the page (200, no code to scan or enter); token redeems
to a 7-day browser session; reuse -> 410 `token_already_used`; unknown
token -> 404; expired token -> 410 `token_expired` (via a second backend
with `CONNECT_TOKEN_TTL_MS=100`); session status/disconnect; leaderboard
scoring (buyerone.ai 13 rank 1, buyertwo.ai 7 rank 2, group message
excluded, on-chain honestly unavailable); Blue Tick quote/status;
600-char write gate (rejected without tick, allowed with tick, rejected
after expiry); plain buy + confirm (receipt event verified); discount
voucher authorize (2.5 USDT) + on-chain buy + confirm + marked used
once; second authorize reserved (409); free voucher redeem + mint;
legacy migration (200 remaining days) + second migration 409; legacy
claim 410 `use_nft_purchase`; public voucher preview (50% OFF, 2.5 USDT,
no `usedBy`); expiry -> benefit off -> renew same token -> benefit back
on, no second mint.

## Contract suite covers

Plain buy; one-per-wallet; soulbound transfer/approve reverts; expiry
(`isActive` false, `isExpired` true, `activeBalanceOf` 0, `balanceOf`
still 1); renew of expired token (same tokenId, no new mint, expiry
from renewal time); active renew extends from old expiry; non-owner
renew reverts; free-voucher mint (amount 0); discount mint at 2.5 USDT;
bad auth / replayed nonce / expired deadline revert.

## Harness bugs found and fixed (2026-11-20)

These are test-harness bugs, not backend bugs. Each is documented so
nobody "fixes" the backend for a harness artifact.

1. **`GET /connect` 404 — missing file in the harness copy.** The
   harness copied only `backend/` into the temp dir, but
   `connect-link.js` serves `connect.html` from the repo root
   (`path.join(__dirname, '..', 'connect.html')`). Fix: the harness
   copies `connect.html` next to the backend copy, mirroring the
   production layout. Production path was always correct.
2. **Expired-token test via cross-process `_tokens`.** The harness
   `require()`d the backend copy's `connect-link.js` in its own
   process, which creates a SEPARATE tokens Map from the one the
   backend child process uses — backdating it did nothing. Fix: the
   token TTL is env-overridable (`CONNECT_TOKEN_TTL_MS`, production
   default 10 min unchanged) and expiry is tested against a second
   backend started with a 100ms TTL.
3. **`send` dotfile 404 on `.tmp-e2e`.** Express's `send` module
   returns 404 for any path containing a dot-prefixed segment
   (`dotfiles: 'ignore'` default). The temp dir was named `.tmp-e2e`,
   so `res.sendFile` 404'd even though the file existed and was
   readable. Fix: temp dir renamed to `tmp-e2e` (no leading dot).
4. **solc Cancun/MCOPY vs ganache.** solc 0.8.26 defaults to the
   Cancun EVM target, which emits MCOPY (0x27) for dynamic-memory
   copies (e.g. the mock registry's string-returning `handleOf`
   getter). This ganache (7.9.2) does not execute it: the call reverted
   with "invalid opcode", which surfaced as 403 `no_agent_id` in the
   authorize flow. Fix: `compile.js` pins `evmVersion: 'shanghai'`.
   Shanghai bytecode runs on BSC mainnet (Cancun is a superset there),
   and the tested artifact is the deployed artifact.
5. **10-minute auth deadline vs 366-day time travel.** The voucher
   authorizations carry a 10-minute deadline against block time. The
   expiry test advances ganache time +366 days, so any authorization
   issued after that is instantly expired on chain ("auth expired").
   Fix: the voucher-buy tests run BEFORE the time-travel block (see the
   NOTE comment in `test-backend.js`). Production deadline unchanged.
6. **Post response shape.** The social post endpoint returns
   `{ message: ... }`, not `{ ok: true }`. The "600-char allowed"
   assertion checks `data.message.text.length === 600`.
7. **Renew assertion.** After the reorder, four tokens exist before
   the renew test, so "nextTokenId == 1" is wrong. The test captures
   `nextTokenId` before the renew and asserts it is unchanged after.
